## Root cause of the medico@mantmed.it → 401
`seed_doctor()` (backend/auth.py) sets the doctor account's email to the `DOCTOR_EMAIL` env var at startup. Production `DOCTOR_EMAIL` is still **medico@auscula.it** (stale), so the doctor's email in the DB is medico@auscula.it. Logging in as medico@mantmed.it therefore fails with 401. This will PERSIST on the new revision until DOCTOR_EMAIL is corrected.

## Fix
1. USER — Deployment Panel → Secrets: set `DOCTOR_EMAIL = medico@mantmed.it`, then re-publish. On next startup `seed_doctor()` finds no user with that email, finds the existing doctor (medico@auscula.it) and renames it to medico@mantmed.it (password unchanged — DOCTOR_PASSWORD already matches). Login as medico@mantmed.it / Auscula-Studio-2026 will then succeed.
2. USER (verify) — after that republish, do a failed login on the LIVE URL and re-check Atlas `mantmed.login_attempts`; a new doc confirms the serving revision writes to Atlas (expected). This removes any remaining ambiguity from pre-republish testing.
