## Conclusion

The production database `app-archive-zip-mantmed` contains **only seeded demo/test data** by all observable signals:
- Single `parent` user is an explicit demo account (`genitore.demo@example.com`).
- All 11 patients inserted in one ~20ms batch on the initial-deploy day.
- All consultation timestamps on round hours; all owned by the one doctor account.
- Expected real names (NICOLE/GIORGIO) are absent.

**Caveat:** fiscal codes and guardian emails are encrypted and could not be decrypted with read-only tools, so "realness" of those specific PII fields is **inferred, not byte-verified**. If a definitive check of fiscal codes / guardian email domains is required, it must be done inside the app (which holds the decryption key), not via direct DB reads.

No data was modified.
